Initial audit baseline: `f7d08664c21b25d2080ff5909a59ca07242b09bf`. The tables are maintained as audited gaps close.

## Method and status vocabulary

This audit compares the checked-in implementation with the approved V1 scope. It is evidence about repository source and automated tests, not a production or physical-device qualification result.

- `DONE`: implemented with checked-in automated coverage appropriate to the slice.
- `PARTIAL`: useful implementation exists, but approved V1 behavior is incomplete.
- `MISSING`: no current implementation of the required user-facing slice was found.
- `BLOCKED`: completion requires an external decision, environment, fixture, device, or production operation.

## Ordered implementation backlog

The next work should follow this order unless a new defect or explicit instruction changes priority:

1. **Series episode history** — complete History semantics without conflating it with Continue Watching.
2. **TV/D-pad and adaptive polish** — close screen-specific focus gaps and record emulator evidence while preserving physical qualification as blocked.
3. **Release identity and branding decision** — Application ID, label, icon, TV banner, versioning, and production theme assets.
4. **Admin OWNER 2FA and operations** — required before an internet-facing production deployment.
5. **Physical qualification and release optimization** — target hardware, real provider/media fixtures, R8/resource shrinking, startup, scrolling, playback, and memory measurements.
