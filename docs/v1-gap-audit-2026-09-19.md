## Method and status vocabulary

This audit compares the checked-in implementation with the approved V1 scope. It is evidence about repository source and automated tests, not a production or physical-device qualification result.

- `DONE`: implemented with checked-in automated coverage appropriate to the slice.
- `PARTIAL`: useful implementation exists, but approved V1 behavior is incomplete.
- `MISSING`: no current implementation of the required user-facing slice was found.
- `BLOCKED`: completion requires an external decision, environment, fixture, device, or production operation.

## Ordered implementation backlog

The next work should follow this order unless a new defect or explicit instruction changes priority:

1. **Production signing** — Signing-key custody, restricted access, backup, and recovery are required before a distributable release.
2. **Admin operations** — secret provisioning, external audit anchoring/monitoring, backup/restore proof, log rotation, rollback, and production thresholds are required before an internet-facing deployment.
3. **Physical qualification and release optimization** — target hardware, real provider/media fixtures, R8/resource shrinking, startup, scrolling, playback, and memory measurements.

## Explicitly not pulled into V1

M3U, Stalker/MAC Portal, downloads, cloud sync, user/kids profiles, social features, provider-wide search, full EPG synchronization, CRM, analytics, and Kubernetes remain deferred. They are not counted as V1 gaps.
